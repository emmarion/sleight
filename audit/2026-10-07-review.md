# Reference implementation and self-hosted slc audit

Date: 2026-10-07. Source revision: `1f66758abc6eea101629d62f006b69c717436d62`.

This audit read all 2,471 lines of `DESIGN.md`, then reviewed the reference
checker, interpreter and extractor, and the self-hosted checker, evaluator
and emitter. It used three parallel reviews and focused executable probes.
`CLAUDE.md`, the existing audit index, `BUGS.md`, `OPEN.md` and relevant
implementation notes were checked for context. This document records
observations and interpretations, not changes to the language design.
No implementation or specification changes were made.

The strongest finding is a reproduced reference-extractor wrong-code bug:
an accepted program prints `1` in the reference interpreter and both slc
execution paths, but prints `0` after reference extraction. Two further
correctness issues affect both implementations. A smaller specification
mismatch and an acceptance difference are also recorded below. No new
closed proof of `False` or accepted nonterminating source function was
constructed; this audit does not establish their absence.

R1–R4 appear absent from the current bug and audit indexes. D1 is a
confirmed compatibility difference; its intended resolution needs a
clearer reading or decision about proof availability within a block.

## R1. Reference extraction splits aliases of one mutable cell

Reproducer: [extract_cell_alias.sl](2026-10-07-review/extract_cell_alias.sl).
Additional commands and analysis:
[extract_cell_alias.md](2026-10-07-review/extract_cell_alias.md).

The program allocates a cell, saves its slot, and performs a compile-time
unique write. An IO continuation captures the saved slot and the returned
cell. At runtime it writes `1` into the cell and reads it through a
parameter declared `at` the saved slot.

| Execution | Exit | stdout |
| --- | --- | --- |
| Reference interpreter | 0 | `1` |
| Reference extracted OCaml | 0 | `0` |
| slc `--interpret` | 0 | `1` |
| slc compiled OCaml | 0 | `1` |

These outputs have no trailing newline. The discrepancy also reproduces
with reference extern implementations stripped, and reference extraction
still prints `0` with `--no-templates`. Thus the tested mismatch does not
depend on an extern implementation or extraction template.

The likely cause is visible at the evaluator/extractor boundary:

- `lib/eval.ml:42–46` retains the mutable field array for a unique cell
  write but returns a fresh `VCtor (k, fs)` wrapper around it.
- `lib/extract.ml:191–203` memoizes ordinary constructor blocks by wrapper
  identity, using `v' == v`. Two wrappers around the same array therefore
  become separate emitted blocks.
- By contrast, extern arrays and bytes are keyed by their underlying
  buffers in `lib/extract.ml:184–190` and `216–223`.

DESIGN §§35–37 make a unique cell write's result physically `at` its
input. The saved slot must still name that cell. The generated program
writes one block and reads another, so this appears to violate both the
placement promise and interpreter/compiler agreement. The consequence
could extend to runtime contents governed by erased indices; the concrete
evidence here is wrong output, not a separately demonstrated logical
contradiction.

Repair direction: preserve the identity of the underlying mutable cell
across constant serialization, including old slot words and closure
captures. A regression should compare all four execution paths and also
cover repeated writes and cyclic cell graphs. Repairing only the printed
value would not address the physical identity issue.

## R2. Earlier `at` declarations do not establish facts while checking a telescope

Reproducer: [at_telescope.sl](2026-10-07-review/at_telescope.sl).
Positive control:
[at_telescope_control.sl](2026-10-07-review/at_telescope_control.sl).

```scheme
(def-adts $ (SameSlot : ((Slot) a) (a is b) -> Type)
  enum
  (many MkSame : (erased (Slot) a) -> (SameSlot a a)))

(def-fns _ $ (many f :
    (many (Nat) a)
    (many (Nat) b at a)
    (erased (SameSlot (slot-of a) (slot-of b)) eq) ->
    (many (Nat) r))
  a)
```

Both checkers exit 1 with a value mismatch for argument 2 of `SameSlot`:
expected `(slot-of a)`, got `(slot-of b)`. Both accept the control, which
uses the same `SameSlot` application inside the body after opening the
same `a` and `b at a` parameters. The control prints `0` in all four
execution paths.

DESIGN §3 permits later entries to depend on earlier entries, and §§35–36
say a declared `at` equates the corresponding slots. On that reading,
the later entry should already see the equality.

The implementation appears to postpone it:

- `lib/elab.ml:734–743` computes and stores `place`, but binds the entry
  without installing that placement in the signature's elaboration
  environment.
- `self/elab.sl:5398–5406` similarly computes `atplace`, calls `bind-as`,
  and stores the placement in `MkEntry` before recursing, without
  installing it via `placed-at`.
- Reference `open_tele`, at `lib/elab.ml:351–360`, does install placement
  when the telescope is subsequently opened. This explains the positive
  control.

The demonstrated consequence is rejection of an apparently valid
dependent signature, not unsound acceptance. Return telescopes and
explicit match annotations share machinery and warrant follow-up, but
those additional forms were not independently reproduced here.

Repair direction: make earlier placement declarations available while
checking later entries, preserving the usual telescope scope boundary.

## R3. Final functions with `is` returns produce the wrong driver behavior

Reproducers:
[final_is_thunk.sl](2026-10-07-review/final_is_thunk.sl) and
[final_is_main.sl](2026-10-07-review/final_is_main.sl).

The nullary case is:

```scheme
(def-fns _ $ (many answer : -> (many 7 is n)) 7)
answer
```

The String-to-String case is:

```scheme
(def-fns _ $ (many identity : (many (String) x) -> (many x is y)) x)
identity
```

Both programs are accepted. In the reference interpreter, reference
extracted executable, slc interpreter, and slc compiled executable:

- The first prints `_\n`, instead of `7\n`.
- The second, given `hello\n` on stdin, prints `_\n`, instead of
  `hello\n`.

DESIGN §12 gives an `is` entry the type of its expression. Section 27
selects the driver behavior by the function's parameter and return
types, with no exclusion for `is` entries. These examples therefore
appear to satisfy the specified thunk and String-to-String cases.

The implementations arrive at the same symptom through different code:

- `lib/program.ml:15–17` recognizes only `sg = Ty ...`; an `Is` return
  instead classifies the function as an ordinary printable value.
  `lib/extract.ml:521–529` uses the same classification.
- `self/emit.sl:1091–1111` uses `sg-term` to classify returns. For an
  `SgIs`, that is the value expression, not its type. The thunk is
  classified with the value `7` as its printing type, while the identity
  function's return fails the check for `String`. `self/interp.sl`
  uses this classification too.

Repair direction: classify using each entry's actual type, handling
dependent `is` entries under the appropriate telescope environment, and
use the return's type when generating or invoking its printer. Merely
making both implementations agree would miss this bug: they already
print the same incorrect result.

## R4. Duplicate `Matchable` marks collapse to an inhabited ordinary type

Reproducer:
[duplicate_matchable_mark.sl](2026-10-07-review/duplicate_matchable_mark.sl).

```scheme
(def-adts $ (Box : -> Type) enum newtype
  (many MkBox : (many (Nat) n) -> (Box)))
(let ((many (Matchable enum newtype newtype Box (many MkBox)) m))
  (matchable-of Box))
0
```

Both checkers accept this, and all four execution paths print `0`.
DESIGN §24 explicitly permits writing a mark twice in a `Matchable`
type, then describes such a type as uninhabited because only `def-adts`
creates `Matchable` values. Here a real, singly marked declaration
inhabits the twice-marked type.

`lib/elab.ml:629–636` reduces the mark list to two `List.mem` booleans.
The corresponding self code is at `self/elab.sl:5066–5072`. The term
representations themselves use boolean flags (`lib/term.ml:13` and
`self/core.sl:126`), so repeated marks cannot survive into equality or
opened-object checking.

This is a reproduced specification-conformance issue. No proof of
`False`, runtime representation confusion, or other soundness consequence
was demonstrated from it. A repair consistent with the current text
would need to preserve enough information to distinguish the types;
simply rejecting the former would also differ from §24's stated rule.

## D1. Delegate proof availability differs inside a mutually recursive block

Reproducer: [delegate_sibling.sl](2026-10-07-review/delegate_sibling.sl).

```scheme
(def-fns _ $ (many ident : (many (Nat) x) -> (many (Nat) r)) x)
(def-fns _
  ((many first : (many (Nat) x) -> (many (Nat) r))
    (delegate (ident x)))
  ((many second : (many (Nat) x) -> (many (Nat) r))
    (let ((erased p)) (delegate-of first))
    x))
(second 0)
```

The reference rejects this because `first` has no `Delegate` proof in
scope. Both slc modes accept it and print `0`.

The reference checks all bodies before adding the collected proofs
(`lib/elab.ml:2043–2050`). Self adds a function's proof as soon as that
body has been checked (`self/elab.sl:5883–5894`), making it available
while checking later siblings.

DESIGN §33 rules out a function using its own delegate proof in its
body, but its wording is less explicit about an already checked sibling.
This audit therefore treats D1 as a confirmed acceptance difference,
not a demonstrated soundness defect or an unequivocal specification
violation. The sibling proof in this example follows a successfully
checked delegate body. The intended availability boundary should be
clarified before making the implementations agree.

## Validation and reproducibility

The existing `_build` binaries were older than the checked-out sources.
Fresh binaries were built before interpreting the probes. Regenerating
`self/header.sl` left its content hash unchanged.

- `dune build`: passed.
- `dune test`: **832 tests, 0 failures**.
- The existing self bootstrap check harness, run against a fresh slc:
  **1,729 checks**, comprising **796 matching executions** and **933
  expected refusals**, with **0 failures**. This included compiled
  tests, `--interpret`, and the harness's selected `--no-templates`
  cases. Refusal positions agreed exactly in 859 checks and differed
  only in column in 74.
- Fresh slc compiled its own sources; that result compiled the same
  sources again. **The second- and third-generation OCaml files were
  byte-identical.** Both source compilation passes used
  `--warnings-as-errors`.
- The saved audit probes were independently run through both
  interpreters and, when accepted, extracted, compiled with `ocamlc`,
  and executed through both compiler paths. R1 was also checked with
  native OCaml compilation.

Local detailed logs are in `_build/audit-current/dune-test.log`,
`slc-results.txt`, and `probe-results.json`. Those are build artifacts;
the small source reproducers are retained beside this report.

From the repository root, with the OCaml toolchain on `PATH`, the fresh
audit compiler can be rebuilt as follows:

```sh
dune build
python3 self/gen_header.py
mkdir -p _build/audit-current
_build/default/bin/main.exe --warnings-as-errors \
  self/base.sl self/heap.sl self/reader.sl self/core.sl self/eval.sl \
  self/elab.sl self/header.sl self/emit.sl self/interp.sl self/main.sl \
  --extract _build/audit-current/slc.ml
ocamlfind ocamlopt -package zarith,unix -linkpkg \
  _build/audit-current/slc.ml -o _build/audit-current/slc
```

For example, R3 can be reproduced on both interpreters with:

```sh
_build/default/bin/main.exe audit/2026-10-07-review/final_is_thunk.sl
_build/audit-current/slc --interpret audit/2026-10-07-review/final_is_thunk.sl
```

R1's companion note gives the complete interpreter/extraction commands.
The same pattern applies to the other accepted probes. For the main
function probe, supply `hello` followed by a newline on stdin.

## Soundness assessment and limits

The review inspected forced unification, canonicalization, occurs and
escaping-binder checks, opened-object merging, `Subterm` and `Predates`
construction and call checking, branch fact scoping, uniqueness and
placement handling, erasure, compile-time values, runtime representation,
and final-value execution. These were source reviews and targeted tests,
not exhaustive verification of every path or a metatheoretic proof.

Several existing obligations remain material:

1. **Consistency and termination.** `OPEN.md` items 1 and 5 remain
   unresolved. `Type : Type` and unrestricted positivity, together
   with the restricted type grammar and explicit decrease discipline,
   need an argument specific to this language. This review supplies
   neither a paradox nor a consistency proof. Host resource exhaustion
   alone is not a counterexample under DESIGN §31.
2. **Erasure and placement conservativity.** `OPEN.md` items 2 and 3
   remain unproved. R1 demonstrates that one implementation boundary
   currently fails physical slot identity even on accepted, terminating
   input. Passing the existing tests or reaching a bootstrap fixpoint
   cannot establish these invariants.
3. **Evaluator trust.** As DESIGN §29 and `OPEN.md` item 4 recognize,
   `comptime-match` can turn evaluated data into checking facts.
   `BUGS.md` item 18 already records self-evaluator fallback values and
   error blocks that do not necessarily abort evaluation. This remains
   a soundness-relevant review target. No new reachable failing-step
   example is claimed here, and this report does not relabel that
   existing issue as a new discovery.
4. **Other bounded traversals.** Source review found depth-limit
   fallbacks in self printing, including `show-at` around
   `self/elab.sl:4158` and printer generation in `self/emit.sl`.
   Whether accepted inputs can reach those limits and silently alter
   output was not reproduced in this audit. This is an unverified
   follow-up concern, not an additional confirmed finding.

The suggested repair order is R1 first, then R2 and R3, followed by R4
and clarification of D1. Each repaired behavior should receive a
targeted regression; the baseline suites currently pass despite all
the reproduced issues above.
